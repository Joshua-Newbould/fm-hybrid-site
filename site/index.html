How the two methods work

Flow matching

Flow matching learns a velocity field that carries samples from Gaussian noise toward the data distribution. During training, we sample a random time t uniformly from [0,1], blend the data x1 and noise x0 at that time to create xt, and train a network to predict the true velocity vt = x1 - x0. The network sees the input (xt, t) and minimizes mean squared error between its velocity prediction and the target. At inference, we start from noise and integrate this learned velocity field forward in time to generate new samples.

The hybrid approach

The hybrid method splits each velocity component into quantisation buckets. Each component uses 16 Gray-coded buckets spanning the range [-6, 6]. For each component, a 16-way softmax head predicts a probability over the buckets. The head is called joint because it predicts all four bits of the Gray code at once, not one bit at a time. Rather than selecting the bucket with the highest probability, we compute the expected value by taking a weighted sum of the bucket centres, each weighted by its predicted probability. Soft decoding changes the velocity the sampler sees and the target the offset head trains against. The bucket probabilities themselves are trained only by the cross-entropy against the true bucket.

The quantisation alone does not fully capture the target velocity, so the model learns an offset head that predicts the remaining difference. The offset is trained by minimising the squared error between the true velocity and the soft-decoded centre plus the offset, with the centre held fixed so that this error does not reach the bucket probabilities. The final velocity prediction combines both: the expected value from the quantised buckets plus the learned correction.

Development and results

We tested multiple configurations in sequence. Early iterations used hard decoding (selecting the highest-probability bucket), which produced poor results around 0.2. Switching to soft expected-value decoding dropped error dramatically. We then experimented with different numbers of bits, the range R, and different training weight schemes. Switching from four per-bit outputs to the 16-way joint head gave the best run on both datasets. No run removed the offset head, so its contribution was not measured on its own.

The best configuration on both datasets is joint16_expect: 16 Gray-coded buckets with joint softmax heads and expected-value decoding. On moons, it achieves 0.01324 compared to baseline 0.01105. On gaussians8, it achieves 0.00765 compared to baseline 0.00486. The hybrid did not meet the success criterion of staying within one baseline standard deviation on both datasets. The results do not say why. The hybrid has more outputs and two loss terms to balance, and three seeds leave wide error bars, so the gap may be noise, tuning, or a real cost of predicting a velocity through buckets.
